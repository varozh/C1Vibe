# Отчёт по премиям сотрудников — расчёт показателей по новым правилам

Внешний отчёт «Отчет по премиям сотрудников» (Розница, справочник «Внешние обработки», папка «Бухгалтерские», код `ЦБР000143`) переведён на схему расчёта показателей отчёта конфигурации `ЛЕЕ_ПоказателиСотрудниковАТТНовыеПравила` («Отчет по показателям сотрудников АТТ (новые правила) v_1.02»).

- `ОтчетПоПремиямСотрудников.erf` — готовый отчёт.
- `ОтчетПоПремиямСотрудников_исходный.erf` — файл, выгруженный из базы 13.11.2026 (28 836 байт; модуль совпадает с `Розница\Reports\ОтчетПоПремиямСотрудников`).
- `ObjectModule_orig.bsl` — исходный модуль, `src\` — исходники нового отчёта (меняется только `Ext\ObjectModule.bsl`, форма и макет не тронуты).
- Сборка: `1cv8.exe` 8.3.12, `DESIGNER /F <база с конфигурацией Розницы> /LoadExternalDataProcessorOrReportFromFiles src\ОтчетПоПремиямСотрудников.xml ОтчетПоПремиямСотрудников.erf`. **Только в базе с конфигурацией Розницы** (например, файловая база, в которую загружена выгрузка `Розница` через `/LoadConfigFromFiles`). В пустой базе конфигуратор при выгрузке и сборке молча меняет тип реквизита формы «Магазин» (`СправочникСсылка.Магазины`) на строку, и выбор магазина перестаёт работать. Первая сборка 13.11.2026 была сделана так и имела эту ошибку; файл пересобран.

## Что перенесено из отчёта ЛЕЕ

Изменения сделаны во всех трёх запросах: по магазину (директор), по продавцам и по продавцам за прошлый месяц (по нему определяется статус продавца и процент премии 3/4/5 %). В коде они помечены комментарием `Новые правила`.

| Показатель | Было | Стало (как в ЛЕЕ) |
|---|---|---|
| Товары для КПЧ | группы из поля «Номенклатура» формы (21 группа KPI), без дождевика | все товары, кроме групп галантереи (`ГруппыГалантереи()`: ремни, платки, бижутерия, галантерея, подарочные и внутренние сертификаты, оборудование, пакеты, SoLi's, DUTY STYLE), видов «Пакет» и «Внутренний подарочный сертификат», дождевика и подарочных карт |
| Знаменатель КПЧ и СЧ | чеки продажи без подарочных карт | чеки, в которых есть хотя бы один товар не из галантереи |
| Средний чек | (выручка − оплата сертификатом − продажа подарочных карт) / чеки без карт | (выручка без галантереи и подарочных карт − оплата сертификатом) / чеки без галантереи |


Не менялось: конверсия — посещаемость по-прежнему берётся из регистра `УмКо_СтатистикаПосещаемости` (ЛЕЕ берёт её из `УмКо_СтатистикаПосещаемостиСводно`; по решению 13.11.2026 оставлен старый регистр; за октябрь 2026 входы по магазинам BL в обоих регистрах совпадают). Также не менялись выручка и план по сумме, сопутка, шкала премии директора (`ПроцентВыполнения1–6`), премии за KPI, проценты продавцов, конверсия продавца по рабочим дням.

Нормы KPI (конверсия, КПЧ, СЧ, коэффициент конверсии) по-прежнему берутся из документа «План продаж». ЛЕЕ берёт их из регистра `ПлановыеПоказателиKPIМагазинов`, но на 13.11.2026 значения в документе и регистре совпадают во всех магазинах за октябрь–декабрь 2026, а поля для премий (`ПроцентВыполнения1–6`, план сопутки, число продавцов) есть только в документе.

Поле «Номенклатура» (группы для расчёта KPI) на форме осталось, но на расчёт больше не влияет. За октябрь 2026 по магазинам BL эти 21 группа и список исключаемых групп ЛЕЕ делят продажи без пересечений и пропусков, то есть состав товаров для КПЧ совпадает.

Попутно исправлено: при пустом поле «Магазин» запрос за прошлый месяц подменялся текстом запроса по ежедневным отчётам (`СтрЗаменить(Запрос.Текст, …)`), и расчёт статуса продавцов по всем магазинам падал.

Вместо всей папки «2. ГАЛАНТЕРЕЯ» теперь только её подпапки 2.06 и 2.07, добавлена 2.9.6. Ремней в справочнике две папки: «1.1.25. РЕМНИ» (с точкой, внутри «2. ГАЛАНТЕРЕЯ») продаж в 2026 году не имеет, все продажи ремней (4,4 млн руб. с начала года) идут через «1.1.25 РЕМНИ» (собственное производство), поэтому в списке обе. ## Магазин при открытии (13.11.2026)

При открытии отчёта поле «Магазин» пустое, даже если в сохранённой настройке он указан (`ПриОткрытии`: после `ЗагрузитьНастройкиОтчета()` — `Магазин = Справочники.Магазины.ПустаяСсылка()`). Остальные поля сохранённой настройки применяются как раньше; кнопка «Выбрать настройку» подставляет магазин из настройки.

## В конфигурации: Отчеты → Сотрудники, финансы, мотивация

В интерфейсе «Полный» в меню «Отчеты → Сотрудники, финансы, мотивация» уже есть пункт «Отчет по премиям сотрудников». Он открывает отчёт конфигурации `БЛ_ОтчетПоПремиямСотрудников`, поэтому меню не меняется — меняется сам отчёт. В других интерфейсах (Менеджер, Бухгалтер и др.) этого подменю нет.

Перенос — копированием текста двух модулей в конфигураторе. Тексты лежат в папке `config\`:

| Файл | Куда |
|---|---|
| `БЛ_ОтчетПоПремиямСотрудников_МодульОбъекта.bsl` | модуль объекта отчёта (расчёт по правилам ЛЕЕ; совпадает с `src\...\Ext\ObjectModule.bsl`) |
| `БЛ_ОтчетПоПремиямСотрудников_МодульФормы.bsl` | модуль формы «ФормаОтчета» (стандартная сопутка, магазин не подставляется, сохранённые настройки) |

Текущая форма отчёта в конфигурации (выгрузка 12.11.2026) подходит без изменений: те же реквизиты (`НачалоПериода`, `КонецПериода`, `Магазин` — «Справочник: Магазины», `Номенклатура`, `ГруппыСопутки`) и элемент `ТабДок1`; события `ПриОткрытии`, кнопки «Сформировать» и «...» периода назначены на процедуры с теми же именами. Кнопок «Сохранить настройки» / «Выбрать настройку» на этой форме нет — их процедуры в модуле есть, но вызываться не будут; при открытии применяется последняя сохранённая во внешнем отчёте настройка (общий ключ хранилища `БЛ_ОтчетПоПремиямСотрудников`). Если кнопки нужны — добавьте на форму две кнопки и назначьте действия `КнопкаСохранитьНастройкиНажатие` и `КнопкаВыбратьНастройкуНажатие`.

Оба модуля компилировались в локальной копии конфигурации (синтаксический контроль: толстый клиент, сервер, внешнее соединение — ошибок по отчёту нет). **В рабочую базу ничего не загружалось.**

### Как перенести (`bl-isoflex/retail`, конфигуратор)

Сделайте резервную копию конфигурации («Конфигурация → Сохранить конфигурацию в файл»). Изменения конфигурации центральной базы РИБ уйдут в узлы при обмене.

1. Отчеты → `БЛ_ОтчетПоПремиямСотрудников` → «Открыть модуль объекта»: выделить всё (Ctrl+A), вставить текст из `БЛ_ОтчетПоПремиямСотрудников_МодульОбъекта.bsl`.
2. Формы → `ФормаОтчета` → вкладка «Модуль»: выделить всё, вставить текст из `БЛ_ОтчетПоПремиямСотрудников_МодульФормы.bsl`.
3. «Конфигурация → Проверка модулей» (или F7 сразу) — ошибок по отчёту быть не должно.
4. Сохранить и обновить конфигурацию базы данных (F7).
5. Проверить: «Отчеты → Сотрудники, финансы, мотивация → Отчет по премиям сотрудников», Аквамолл за октябрь: у директора КПЧ 1,88, средний чек 17 586,61 (как в отчёте ЛЕЕ).

После переноса внешний отчёт `ЦБР000143` можно не использовать (он и так помечен на удаление).

## Проверено

- Отчёт собран конфигуратором 8.3.12 без ошибок.
- Тексты всех трёх запросов из нового модуля выполнены на рабочей базе (только чтение) с параметрами отчёта. «Business Line Улн ТЦ Аквамолл», октябрь 2026: по магазину и по каждому продавцу выручка, количество товаров, чеки без галантереи, КПЧ, СЧ и конверсия **совпали** с запросами отчёта ЛЕЕ (магазин: КПЧ 1,88, СЧ 17 586,61, конверсия 7,9). После возврата старого регистра посещаемости запросы выполнены повторно — результаты те же.
- Запрос за прошлый месяц (сентябрь) по тому же магазину: КПЧ продавцов совпал с ЛЕЕ, СЧ — у всех, кроме Гончаровой М. Ю. (23 831,78 против 23 733,91). Отчёт по премиям считает показатели прошлого месяца только за дни, на которые у продавца есть ежедневный отчёт, а ЛЕЕ — за весь месяц. Это прежнее правило отчёта по премиям, оно сохранено.
- Сам отчёт целиком (форма, макет, премии) в базе **не запускался**: через COM-подключение платформа требует подтвердить открытие внешнего файла (защита от опасных действий).

## Как загрузить

1. Откройте `ОтчетПоПремиямСотрудников.erf` через «Файл → Открыть» и сформируйте отчёт за октябрь для пары магазинов, сравните с отчётом ЛЕЕ.
2. В справочнике «Внешние обработки» откройте элемент `ЦБР000143` «Отчет по премиям сотрудников» (папка «Бухгалтерские») и замените файл на новый. Сейчас элемент **помечен на удаление** — снимите пометку, если отчёт нужен.
