# Акция на платья: одно платье за каждый товар собственного производства (Розница 1.0)

Доработка общего модуля `УправлениеМаркетинговымиАкциями` для базы `bl-isoflex/retail`. Скидка 1686 «Скидка 50% на Платья + Собственное производство» даёт 50% на столько платьев, сколько в чеке товаров собственного производства (СП).

- `Module.bsl` — исправленный модуль целиком.
- `Module.orig.bsl` — исходный модуль из выгрузки `Розница\CommonModules\УправлениеМаркетинговымиАкциями\Ext\Module.bsl`. Нужен для сравнения и отката.

Все изменённые места помечены комментарием `// Акция платья по товарам СП 13.11.2026`.

## Итоговые правила акции

Платьев со скидкой 50% = большее из двух чисел:
- товаров СП в чеке (но не больше, чем платьев) — скидка 1686;
- по одному платью за каждую пару платьев — скидка 1688.

30% (процент скидки 1687) получают:
- единственное платье в чеке без товаров СП;
- в чеке из **трёх платьев** — первое платье без 50%, если 50% получило только одно платье.

Скидку получают самые дешёвые платья. Остальные платья идут без скидки.

| Чек (платья от дешёвого к дорогому) | Скидки |
|---|---|
| 1 платье | 30% |
| 1 платье + 1 СП (или больше) | 50% |
| 2 платья | 50%, 0 |
| 2 платья + 1 СП | 50%, 0 |
| 2 платья + 2 СП | 50%, 50% |
| 3 платья | 50%, 30%, 0 |
| 3 платья + 1 СП | 50%, 30%, 0 |
| 3 платья + 2 СП | 50%, 50%, 0 |
| 3 платья + 3 СП | 50%, 50%, 50% |
| 4 платья | 50%, 50%, 0, 0 |
| 4 платья + 1 СП | 50%, 50%, 0, 0 |
| 4 платья + 3 СП | 50%, 50%, 50%, 0 |

Чеки, где работают сразу две скидки папки (3 платья + 1 СП, 4 платья + 1 СП), правильно считаются в РМК только с правкой формы (см. «Только эта скидка» ниже).

## Что изменено в коде

Новый вид скидки «цикличная по товарам условия». Модуль распознаёт его по настройкам, отдельный реквизит не нужен:
- «Дополнительное условие» = «Цикличная скидка»;
- «Условие предоставления» = «По количеству»;
- «Сегмент номенклатуры» (условие) и «Сегмент базы расчёта» (на что скидка) заполнены и **различаются**;
- «Значение условия» > 0 и «Значение условия макс» > 0.

Для такой скидки: на каждые «Значение условия» штук товаров из сегмента условия скидку получают «Значение условия макс» штук товаров базы, от дешёвых к дорогим. Строки сверх лимита удаляются из таблицы скидок, а не обнуляются. Поэтому в папке «Вытеснение» на эти платья может встать следующая скидка (1688). Поле «Цикличность» для такой скидки не используется.

Из действующих сейчас скидок под это описание попадает только 1686 (проверено запросом по справочнику 13.11.2026). Остальные цикличные скидки (1614, 1533, 1564, 1626, 1630, 1688) имеют одинаковые сегменты или пустые и считаются по-старому.

| Место | Что сделано |
|---|---|
| `ДополнитьТаблицуСкидок`, перед блоком цикличных скидок | вызов `ОграничитьСкидкиПоТоварамУсловия` |
| `ДополнитьТаблицуСкидок`, блок цикличных скидок | такие скидки исключены из общего цикла: иначе 1686 и 1688 складывались бы (3 платья + 1 СП давали бы 2 платья) |
| новые `ЭтоСкидкаПоТоварамУсловия`, `КоличествоТоваровСегмента`, `ОграничитьСкидкиПоТоварамУсловия` | расчёт лимита и удаление лишних строк |
| `ДополнитьТаблицуСкидок`, после блока цикличных скидок; новая `ДобавитьСкидкуНаВтороеИзТрехПлатьев` | если у скидки 1688 ровно 3 платья, первому платью без 50% ставится процент скидки 1687 (30%) |

Про 30% на второе из трёх платьев:
- Коды 1688 и 1687 записаны в процедуре `ДобавитьСкидкуНаВтороеИзТрехПлатьев`. Процент берётся из скидки 1687: если поменять его в справочнике, изменится и здесь.
- В чеке эта скидка будет называться «Скидка 50% на Платье + Платье», но с процентом 30.
- При 4 платьях и больше 30% не даётся.

## Что нужно настроить в базе

1. **Порядок применения в папке «Вытеснение по ММ -30/50% на платья»:** 1686 → **1**, 1688 → **2**, 1687 → 3. Сейчас стоит 1688 = 1, 1686 = 2. Без этой перестановки 1688 вытеснит 1686 при двух платьях и больше.
2. Скидка 1686 оставить как сейчас: «Цикличная скидка», «По количеству», «Значение условия» = 1, «Значение условия макс» = 1, «Сегмент номенклатуры» = «Собственное производство 2026 без платьев», «Сегмент базы расчёта» = «Платья 2026».
3. 1688 и 1687 не менять.

## «Только эта скидка» в РМК: правка формы

В форме РМК (`ЧекККМ`, `ФормаРегистрацииПродаж`, процедура `КнопкаРасчетСкидокНажатие`) при флаге «Только эта скидка» в чеке остаётся **одна** скидка с ненулевой суммой, все остальные убираются. В чеках «3 платья + 1 СП» (1686 — 50%, 1688 — 30%) и «4 платья + 1 СП» (1686 и 1688 по 50%) работают сразу две скидки. Без правки формы кассир увидит только одну из них.

Правка — в файле `ФормаРМК_фрагмент.bsl`: в одном условии скидки с флагом «Только эта скидка» из той же папки, что и оставленная скидка, больше не убираются. Остальные скидки, в том числе бонусные, убираются как раньше.

Ещё одно ограничение: вытеснение в типовом коде работает по номенклатуре и характеристике, а не по строке чека. Два одинаковых платья одного размера отдельными строками получают одну и ту же скидку из папки. Это поведение было и раньше.

## Как внести

1. Сделайте копию базы или выгрузите конфигурацию (`.cf`).
2. Конфигуратор → Общие модули → **УправлениеМаркетинговымиАкциями** → выделите весь текст модуля (Ctrl+A) и замените его содержимым `Module.bsl`.
3. Документы → **ЧекККМ** → Формы → **ФормаРегистрацииПродаж** → модуль формы. Найдите (Ctrl+F) `должнаБытьТолькоОднаАкцияИПакет = 0` и замените условие ниже по `ФормаРМК_фрагмент.bsl`.
4. Синтаксический контроль (Ctrl+F7), затем обновление конфигурации БД (F7).
5. Поменяйте порядок применения 1686 и 1688 (см. выше).
6. Магазины через РИБ получат конфигурацию со следующим обменом. Её нужно применить в каждом узле.

Откат: вставить в модуль `Module.orig.bsl`, вернуть условие в форме (блок «БЫЛО») и порядок 1688 = 1, 1686 = 2.

## Как проверить

В магазине, где действует документ акции (сейчас ЦБР00000023, только «ОФИС»), пробейте в РМК чеки из таблицы выше. Используйте платья с ценой на 5. На товары с другой ценой скидки с флагом «Маркетинг» не встают.

- Сегменты «Собственное производство 2026 без платьев» (92 619 позиций) и «Платья 2026» (21 263) не пересекаются.

- Синтаксический контроль и работа в РМК **не проверялись**: у меня нет доступа на изменение конфигурации. Сначала проверьте на копии базы.
