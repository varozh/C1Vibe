# Розница: автообновление конфигурации при обмене РИБ на серверной базе (11.11.2026)

Общий модуль `ПроцедурыОбменаДанными` конфигурации Розница 1.0.
Полный текст исправленного модуля — `src\ПроцедурыОбменаДанными.Module.bsl`.

## Проблема

Когда периферийный узел (магазин) принимает пакет от главного узла с изменениями конфигурации
(«обмен с применением»), срабатывает `ЗагрузитьCообщениеСИзменениямиОтРИБУзла`:

1. Показывает окно `WScript.Shell.Popup` **без таймаута**. Если обмен идёт регламентным заданием
   на сервере 1С, окно никто не видит и не закрывает — сеанс зависает навсегда и держит базу.
2. Запускает `Upd1C.bat` из константы «Настройка файла обновления конфигурации». Текст скрипта
   (его пишет модуль приложения при каждом запуске) рассчитан на файловую базу:
   `taskkill /F /IM 1cv8.exe`, `/F<каталог>`, путь вырезан из строки `File="..."`.
   Для серверной базы путь получается мусорный, а убитый `taskkill` клиент остаётся сеансом
   на сервере 1С и блокирует `/UpdateDBCfg` — Конфигуратор висит в диалоге.

## Что изменено

Для **файловой** базы поведение прежнее. Для **клиент-серверной**:

- `ЗагрузитьCообщениеСИзменениямиОтРИБУзла` — вместо `WScript.Shell.Popup` на клиенте показывается
  `Предупреждение` с таймаутом 30 с; на сервере (регламентное задание) окна не показываются.
- `ПредложитьПерезагрузкуПрограммы`:
  - на сервере 1С скрипт не запускается — в журнал регистрации пишется предупреждение
    «Обмен данными.Обновление конфигурации»; сеанс завершается, база свободна для обновления;
  - на клиенте скрипт формируется новой функцией `СформироватьТекстБатФайлаОбновленияСервернойИБ`
    (сохранённый в константе файловый скрипт игнорируется), после запуска скрипта программа
    закрывается штатно `ЗавершитьРаботуСистемы(Ложь)`.
- Новая функция `СформироватьТекстБатФайлаОбновленияСервернойИБ`: без `taskkill`, подключение
  `/S"Сервер\База"`, ожидание 30 с отключения сеанса, Конфигуратор с `/DisableStartupDialogs`
  (не ждёт ответа в диалоге), до 5 попыток с паузой 60 с, протокол `%TEMP%\Upd1C_server.log`,
  затем запуск 1С под «Продавец-консультант». Если обновить не удалось — открывается протокол.

Логины/пароли («Администратор», «Продавец-консультант») те же, что уже прописаны в модуле приложения.

## Как установить

Доработка ставится один раз — в **главный узел** (центральная база Розницы). В магазины она
приходит сама, обычным обменом РИБ, как любое изменение конфигурации.

### Что нужно заранее

- Платформа 1С **8.3** на компьютерах магазинов с серверной базой: ключ `/DisableStartupDialogs`
  в 8.2 не поддерживается.
- В базах магазинов есть пользователи «Администратор» и «Продавец-консультант» с паролями,
  прописанными в модуле приложения. Модуль приложения создаёт их сам при запуске узла.
- Права администратора в Конфигураторе главного узла и окно, когда можно получить монопольный доступ.

### Шаг 1. Резервная копия главного узла

Конфигуратор → **Администрирование → Выгрузить информационную базу…** → сохранить `.dt`.
Дополнительно: **Конфигурация → Сохранить конфигурацию в файл…** → `.cf` (для быстрого отката).

### Шаг 2. Внести изменения в модуль

1. Конфигуратор главного узла → **Конфигурация → Открыть конфигурацию**.
2. Если конфигурация на поддержке и модуль закрыт: **Конфигурация → Поддержка → Настройка поддержки**
   → «Включить возможность изменения»; для модуля `ПроцедурыОбменаДанными` — «Объект поставщика
   редактируется с сохранением поддержки».
3. Дерево конфигурации → **Общие модули → ПроцедурыОбменаДанными** → открыть модуль.
4. Перенести изменения одним из способов.

**Способ А — заменить модуль целиком.** Подходит, только если модуль в базе не менялся после
выгрузки, из которой сделана доработка. Проверка: в открытом модуле **Файл → Сохранить копию…** →
сохранить текст во временный файл, затем **Файл → Сравнить файлы** — сравнить его с
`src\ПроцедурыОбменаДанными.Module.bsl`. Если отличаются только три места из способа Б —
выделить весь текст модуля (Ctrl+A) и вставить текст из `src\ПроцедурыОбменаДанными.Module.bsl`.

**Способ Б — перенести три фрагмента вручную** (поиск в модуле — Ctrl+F). Готовые фрагменты
берите из `src\ПроцедурыОбменаДанными.Module.bsl`.

| № | Где искать в модуле базы | Что сделать |
|---|---|---|
| 1 | Строка `Процедура ПредложитьПерезагрузкуПрограммы(` | **Перед** её комментарием вставить функцию `СформироватьТекстБатФайлаОбновленияСервернойИБ()` целиком (в `src` — от комментария «Функция формирует текст BAT-файла обновления конфигурации для клиент-серверной ИБ» до `КонецФункции`). |
| 2 | Внутри `ПредложитьПерезагрузкуПрограммы` | Начало процедуры (`Если СтруктураПараметров = Неопределено Тогда … КонецЕсли;`) заменить на блок из `src` — от `// Для клиент-серверной ИБ сохраненный в константе скрипт` до `КонецЕсли;`. После строки `ЗапуститьПриложение(ИмяБАТФайла);` добавить блок `Если Не ЭтоФайловаяИБ Тогда … ЗавершитьРаботуСистемы(Ложь); КонецЕсли;`. |
| 3 | Процедура `ЗагрузитьCообщениеСИзменениямиОтРИБУзла`, строка `WshShell=новый COMОбъект("WScript.Shell");` | Вызов `WshShell.Popup(...)` обернуть в `Если ОпределитьЭтаИнформационнаяБазаФайловая() Тогда … Иначе … КонецЕсли;` — блок целиком взять из `src`. |

5. **Модуль → Проверить синтаксис** (Ctrl+F7) — ошибок быть не должно.

### Шаг 3. Обновить конфигурацию главного узла

**Конфигурация → Обновить конфигурацию базы данных** (F7), подтвердить изменения. В главном узле
РИБ изменения конфигурации автоматически регистрируются к отправке во все подчинённые узлы.

### Шаг 4. Отправить изменения в магазины

Выполнить обмен с узлами плана обмена «По магазину» (вручную или дождаться автообмена).

**Магазины с файловой базой** — ничего не меняется: изменения применяются старым способом,
окно «В конфигурацию загружены изменения», 1С перезапускается сама.

**Магазины с серверной базой — только в первый раз** изменения применит ещё старый код,
и сеанс может зависнуть так же, как раньше. Обновить такой узел вручную:

1. Консоль администрирования серверов 1С → кластер → информационная база магазина → **Сеансы** —
   удалить зависший сеанс (обычно «Фоновое задание» или сеанс пользователя, принимавшего обмен).
   Если есть окно `WScript`/`Popup` на сервере — закрыть или завершить процесс `rphost`
   только этого сеанса.
2. Конфигуратор узла магазина (подключение `/S"Сервер\База"`) →
   **Конфигурация → Обновить конфигурацию базы данных** (F7).
3. Запустить 1С и повторить обмен — чтобы догрузились данные, которые не прочитались в прошлый раз.

Начиная со следующего изменения конфигурации серверные узлы работают по новой логике.

### Шаг 5. Проверка

- В серверной базе магазина откройте модуль `ПроцедурыОбменаДанными` в Конфигураторе — в нём
  есть функция `СформироватьТекстБатФайлаОбновленияСервернойИБ`.
- При следующем изменении конфигурации из главного узла:
  - обмен из программы → короткое предупреждение, 1С закрывается, открывается окно скрипта
    «НЕ ЗАКРЫВАЙТЕ ЭТО ОКНО!», через 0,5–5 мин 1С запускается сама; протокол —
    `%TEMP%\Upd1C_server.log` на компьютере пользователя;
  - обмен регламентным заданием → сеанс не висит, в журнале регистрации событие
    «Обмен данными.Обновление конфигурации»; обновить базу — обменом из программы или F7 в Конфигураторе.
- Если скрипт после 5 попыток открыл протокол — в базе работали другие пользователи: завершите их
  сеансы и обновите базу в Конфигураторе.

### Откат

Вернуть модуль из сохранённого `.cf` (**Конфигурация → Сравнить, объединить с конфигурацией из
файла…** → отметить только `ПроцедурыОбменаДанными`) или загрузить `.dt`, затем F7 и обмен с магазинами.

## Если в серверной базе обмен идёт регламентным заданием

Изменения конфигурации применятся при следующем обмене, запущенном из программы на клиенте
(или вручную в Конфигураторе). Сообщение — в журнале регистрации, событие
«Обмен данными.Обновление конфигурации».
