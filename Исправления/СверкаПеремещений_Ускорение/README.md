# Ускорение сверки перемещений (Розница 1.0)

Исправление для обработки **«Сверка перемещений»** (`Обработка.СверкаПеремещений`, форма `Форма`) в базе `bl-isoflex/retail`. Продавцы-консультанты открывают её из Меню РМК кнопкой «Принять». Исправление убирает подвисание на несколько секунд после каждого отсканированного штрихкода.

- `Module.bsl` — исправленный модуль формы целиком.
- `Module.orig.bsl` — исходный модуль, извлечённый из выгрузки `Розница\DataProcessors\СверкаПеремещений\Forms\Форма\Ext\Form.bin`. Он нужен для сравнения и отката.

Все изменённые места в коде помечены комментарием `// Ускорение сверки 11.11.2026`.

## Почему висело

После каждого скана (`СШКОбработатьШтрихкод` → `НайтиПоШКНажатие` → `ПоискПоштрихКоду` → `СШКНоменклатура`) выполнялось:

1. **`СохранитьВоВременныйФайл`.** Вся таблица «Товары» выводилась построителем отчёта в табличный документ, а затем удалялся и заново записывался `%TEMP%\Temp.mxl`. Построитель получает с сервера представления номенклатуры, характеристики и единицы измерения для каждой строки, поэтому чем больше строк в перемещении, тем дольше пауза. С 01.08.2026 в перемещении в среднем 18 строк, максимум 287.
2. **Поиск штрихкода через `ПОДОБНО`** по регистру «Штрихкоды», в котором около 650 тыс. записей. Запрос ещё и читал три лишних поля через составной тип `Владелец`. С `ПОДОБНО` СУБД может просматривать весь регистр вместо индекса по полю `Штрихкод`. Если в это время обмен записывает штрихкоды, запрос ждёт его блокировок.

## Что изменено

| Место | Было | Стало |
|---|---|---|
| `ПоискПоштрихКоду` | `Штрихкод ПОДОБНО &СтрокаПоиска`, 7 полей | `ВЫБРАТЬ ПЕРВЫЕ 1 … Штрихкод = &СтрокаПоиска`, 3 поля (используются только они) |
| `СШКНоменклатура` | `СохранитьВоВременныйФайл(1)` на каждом скане | `ЗапланироватьСохранение()`: сохранение не чаще раза в 3 секунды |
| `СШКНоменклатура` | `ТоварыПеремещение.ИзменитьСтроку()` | убрано: курсор встаёт на строку, но не переводит её в режим редактирования |
| `СохранитьВоВременныйФайл` | построитель отчёта → `Temp.mxl` | `ЗначениеВФайл` → `%TEMP%\СверкаПеремещений_Temp.dat` (таблица и документ перемещения, без обращений к серверу) |
| `КоманднаяПанельСверкаВосстановление` | читает `Temp.mxl`, ищет номенклатуру по коду, а характеристику по наименованию | читает новый файл и восстанавливает документ и таблицу как есть; если нового файла нет, читает старый `Temp.mxl` по-прежнему |
| `ПриЗакрытии` | — | дописывает несохранённые изменения в файл |
| `СоздатьДокументыНажатие` / `ТоварыПеремещениеПриПолученииДанных` | признак «есть неотсканированные» зависел от последней отрисованной строки | признак считается по всей таблице: есть строка, где «Количество» меньше «Количества по документу» |

Новые процедуры: `ИмяФайлаСверки`, `ИнтервалСохраненияСверки`, `ЗапланироватьСохранение`, `ОбработчикОтложенногоСохранения`, `ВосстановитьИзФайлаСверки`.

Создание приходного ордера, акта расхождений, переоценки и обработка кодов маркировки **не менялись**.

### Что изменится для продавца

- Сканирование идёт без пауз.
- После скана строка подсвечивается, но не открывается для редактирования. Количество вручную по-прежнему можно поправить двойным щелчком.
- «Восстановление» возвращает сверку вместе с документом перемещения. Если открыт другой документ, обработка сначала спросит, восстанавливать ли сверку.
- Вопрос «Вы точно отсканировали весь товар?» появляется только тогда, когда есть недосканированные строки. Раньше он появлялся или не появлялся случайно.

## Как внести

Модуль формы хранится в обычной (не управляемой) форме, поэтому правка вносится в Конфигураторе вручную.

1. Сделайте копию базы или выгрузите конфигурацию (`.cf`).
2. Конфигуратор → Конфигурация → Обработки → **СверкаПеремещений** → Формы → **Форма** → вкладка «Модуль».
3. Выделите весь текст модуля (Ctrl+A) и замените его содержимым `Module.bsl`.
4. Выполните синтаксический контроль модуля (Ctrl+F7), затем обновите конфигурацию базы данных (F7).
5. Если магазины работают через РИБ, конфигурация попадёт в узлы со следующим обменом. Её нужно применить в каждом узле.

Откат: вставить в модуль `Module.orig.bsl`.

## Как проверить

1. Откройте под продавцом-консультантом Меню РМК → «Принять», выберите крупное перемещение (100+ строк) и отсканируйте подряд 10–20 товаров. Пауз после сканов быть не должно.
2. Закройте форму, откройте её снова и нажмите «Восстановление»: таблица должна вернуться с отсканированными количествами.
3. Если нужна точная цифра «до/после»: Отладка → Замер производительности на одной сверке. Раньше основное время уходило на `СохранитьВоВременныйФайл` и `ПоискПоштрихКоду`.

## Проверено

- Новый запрос `ПоискПоштрихКоду` выполнен на рабочей базе в режиме только чтения (штрихкод `2000000045818`). Он вернул ту же номенклатуру, характеристику и единицу, что и старый запрос с `ПОДОБНО`.
- Синтаксический контроль в Конфигураторе и работа формы **не проверялись**: у меня нет доступа на изменение конфигурации. Сначала проверьте на копии базы или в одном магазине.
