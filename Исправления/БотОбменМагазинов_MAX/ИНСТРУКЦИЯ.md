# Установка бота MAX на сервер

Бот каждый день в 20:00 напоминает магазинам в группе MAX выполнить обмен. В 07:00 он присылает список магазинов, которые вечерний обмен не выполнили.

## 1. Что нужно на сервере

| Что | Зачем | Как проверить |
|---|---|---|
| Windows PowerShell 5.1 | на нём работает скрипт | `$PSVersionTable.PSVersion` — 5.1 |
| Платформа 1С **строго версии 8.3.12.1790** | COM-коннектор `comcntr.dll` для подключения к базе. Версия должна совпадать с версией сервера 1С `bl-isoflex`, иначе будет ошибка «Несоответствие версий клиента и сервера» | папка `C:\Program Files (x86)\1cv8\8.3.12.1790\bin` или `C:\Program Files\1cv8\8.3.12.1790\bin`, в ней `comcntr.dll` |
| Зарегистрированный COM-коннектор | без регистрации скрипт не создаст объект `V83.COMConnector` | `-Mode Check`, строка «COM-коннектор 1С» |
| Сетевой доступ к серверу 1С `bl-isoflex` | чтение данных Розницы | порты 1540, 1541, 1560–1591 |
| Доступ в интернет к `platform-api2.max.ru:443` | отправка сообщений в MAX | `Test-NetConnection platform-api2.max.ru -Port 443` |
| Корневой сертификат Минцифры **Russian Trusted Root CA** | сертификат сайта MAX выдан Минцифры. Без корневого сертификата будет ошибка SSL/TLS | `Get-ChildItem Cert:\LocalMachine\Root \| ? Subject -like '*Russian Trusted Root*'` |
| Пользователь 1С с правом внешнего соединения | под ним скрипт читает базу. Скрипт только читает данные: план обмена «ПоМагазину» и регистр «История обмена данными» | `-Mode Check`, строка «Подключение к Рознице» |
| Пользователь Windows, под которым будут работать задачи | от его имени шифруются пароль и токен (DPAPI). Расшифровать их может только он и только на этом сервере | — |

Другие программы ставить не нужно.

## 2. Подготовка сервера

Все команды выполняйте в PowerShell **от администратора**.

### 2.1. Платформа 1С 8.3.12.1790

Если на сервере уже стоит платформа 8.3.12.1790 (клиент или сервер 1С), этот шаг пропустите.

Иначе установите её из того же дистрибутива, что стоит на рабочих местах. Достаточно компонента «1С:Предприятие». Другие версии платформы на сервере не мешают.

### 2.2. Регистрация COM-коннектора

Разрядность PowerShell, в которой будет работать скрипт, должна совпадать с разрядностью зарегистрированного коннектора.

32-битная платформа (папка `Program Files (x86)`), скрипт тогда работает в 32-битном PowerShell:
```powershell
C:\Windows\SysWOW64\regsvr32.exe "C:\Program Files (x86)\1cv8\8.3.12.1790\bin\comcntr.dll"
```

64-битная платформа (папка `Program Files`, обычно так бывает, если на этом сервере стоит сам сервер 1С), скрипт тогда работает в 64-битном PowerShell:
```powershell
C:\Windows\System32\regsvr32.exe "C:\Program Files\1cv8\8.3.12.1790\bin\comcntr.dll"
```

Если позже на сервер поставят другую версию платформы и зарегистрируют её коннектор, скрипт перестанет подключаться. Тогда снова зарегистрируйте `comcntr.dll` от 8.3.12.1790. Обновили платформу сервера 1С — зарегистрируйте коннектор новой версии.

### 2.3. Сертификат Минцифры

Проверьте, установлен ли сертификат:
```powershell
Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -like '*Russian Trusted Root*'
```
Если команда ничего не вывела:
1. Скачайте корневой сертификат «Russian Trusted Root CA» с официальной страницы https://www.gosuslugi.ru/crt (файл для Windows).
2. Установите его в хранилище «Доверенные корневые центры сертификации» локального компьютера. Если файл скачан как `russian_trusted_root_ca.cer`:
```powershell
Import-Certificate -FilePath "C:\Temp\russian_trusted_root_ca.cer" -CertStoreLocation Cert:\LocalMachine\Root
```

### 2.4. Время на сервере

Задачи запускаются по местному времени сервера. Проверьте часовой пояс: в 07:00 и 20:00 по нему должно быть нужное вам время.
```powershell
Get-TimeZone
```

## 3. Установка скрипта

### 3.1. Копирование файлов

Создайте на сервере папку, например `C:\Scripts\MaxExchangeBot`. Скопируйте в неё два файла из `Исправления\БотОбменМагазинов_MAX`:
- `exchange-bot.ps1`
- `config.json`

Если файлы пришли по почте или из интернета, снимите блокировку:
```powershell
Get-ChildItem C:\Scripts\MaxExchangeBot | Unblock-File
```

Пользователь Windows, под которым будут работать задачи, должен иметь право записи в эту папку: туда пишется журнал `exchange-bot.log`.

### 3.2. Выбор PowerShell

Дальше все команды выполняйте **под тем пользователем Windows, под которым будут работать задачи**, и в PowerShell той же разрядности, что и коннектор из п. 2.2. Не обязательно от администратора.

- 32-битный коннектор: `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`
- 64-битный коннектор: `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

В примерах ниже стоит 32-битный. Если у вас 64-битный коннектор, замените в командах `SysWOW64` на `System32`.

### 3.3. Подключение к базе

Откройте `config.json` в Блокноте и проверьте раздел `retail`:
- `server` — `bl-isoflex`, `ref` — `retail`;
- `user` — пользователь 1С, под которым скрипт читает базу.

Зашифрованные пароль и токен, скопированные с другого компьютера, на сервере не расшифруются. Сохраните их заново.

Пароль пользователя 1С (скрипт спросит его):
```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode SetPassword
```

Токен бота MAX (взять на платформе MAX для партнёров, раздел «Чат-боты»):
```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode SetToken
```

### 3.4. Проверка

```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode Check
```
Все строки должны быть `[OK]`, в конце — «Всё готово к работе».

| Ошибка | Что делать |
|---|---|
| COM-коннектор 1С не зарегистрирован для NN-битного процесса | п. 2.2, или запустите PowerShell другой разрядности |
| Несоответствие версий клиента и сервера | зарегистрирован коннектор не той версии: п. 2.2 с версией 8.3.12.1790 |
| Не удалось расшифровать пароль / tokenEnc | п. 3.3 под тем же пользователем Windows |
| Не удалось установить безопасный канал SSL/TLS | п. 2.3, сертификат Минцифры |
| Ошибка (401) | неверный или перевыпущенный токен: `-Mode SetToken` |
| Группа для рассылки: ошибка (404 / 403) | бот не в группе или неверный `chatId`: п. 3.5 |

Посмотреть отчёт без отправки:
```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode Report -DryRun
```

### 3.5. Группа для рассылки

Сейчас в `config.json` записан `chatId` тестовой группы «IT отдел BUSINESS LINE». Чтобы перейти на группу магазинов:
1. Запустите ожидание событий (3 минуты):
```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode ListChats
```
2. Пока идёт ожидание, добавьте бота в группу магазинов. Если бот уже в группе, напишите в ней любое сообщение.
3. Скрипт выведет строку `chat_id = -NNNNNNNN  <название группы>`. Впишите это число в `chatId` в `config.json`.

Запросов `ListChats` не должно быть два одновременно, например на старом компьютере и на сервере. Иначе событие может уйти не туда.

## 4. Задачи в Планировщике

```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\MaxExchangeBot\exchange-bot.ps1 -Mode InstallTasks
```
Скрипт спросит пароль текущего пользователя Windows: он нужен, чтобы задачи работали без входа в систему. Будут созданы две задачи:
- «MAX обмен магазинов - напоминание» — ежедневно в 20:00 (`reminderTime` в `config.json`);
- «MAX обмен магазинов - отчет» — ежедневно в 07:00 (`reportTime`).

Задачи запускают скрипт тем же `powershell.exe`, в котором вы выполнили команду. Если запустить `InstallTasks` повторно, задачи пересоздаются, например после смены времени в конфиге или пароля Windows.

Если пароль пользователя Windows сменится, задачи перестанут запускаться. Выполните `InstallTasks` заново.

Проверка задачи вручную (сообщение уйдёт в группу из `chatId`):
```powershell
Start-ScheduledTask -TaskName 'MAX обмен магазинов - напоминание'
```
```powershell
Get-Content C:\Scripts\MaxExchangeBot\exchange-bot.log -Tail 20 -Encoding UTF8
```

## 5. Настройки в config.json

| Поле | Что задаёт |
|---|---|
| `chatId` | группа, куда отправляются сообщения |
| `eveningFrom` | с какого времени прошлого дня обмен считается вечерним (по умолчанию 20:00) |
| `reminderTime`, `reportTime` | время задач. После изменения выполните `InstallTasks` |
| `exclude` | магазины, которые не нужно показывать в списке: код узла или наименование, например `["BL-ORB-02"]` |
| `reminderText`, `reportHeader`, `reportFooter`, `reportAllOk` | тексты сообщений |

После правки `config.json` сохраните файл в кодировке UTF-8. Блокнот Windows 10/Server 2019 и новее сохраняет в UTF-8 по умолчанию.
