# Начисление доп. бонусов по акции «куртки, пальто, плащи» 22.10–05.11.2026 (Розница 1.0)

Внешняя обработка `НачислениеДопБонусов_АкцияВерхняяОдежда.epf` для базы `bl-isoflex/retail` (платформа 8.3.12, обычное приложение).
Она находит чеки акции и создаёт один проведённый документ «Начисление бонусов покупателей». Каждая дисконтная карта получает **10 000** бонусов **один раз**, сколько бы чеков акции у неё ни было. Тип бонуса — «Дополнительный», срок действия до **30.11.2026 23:59:59**. **Картам сотрудников бонусы не начисляются.**

- `src\` — исходники, вся логика в `src\НачислениеДопБонусов_АкцияВерхняяОдежда\Ext\ObjectModule.bsl`. Формы нет: диалоги открываются сразу при открытии файла.
- Параметры акции (период, папки, сумма, срок) заданы в конце модуля.
- Сборка: `1cv8.exe` 8.3.12, `DESIGNER /F <база> /LoadExternalDataProcessorOrReportFromFiles src\НачислениеДопБонусов_АкцияВерхняяОдежда.xml НачислениеДопБонусов_АкцияВерхняяОдежда.epf`.

## Какие чеки попадают

- Чеки ККМ «Продажа» с 22.10.2026 00:00 по 05.11.2026 23:59:59. Чек должен быть проведён и не помечен на удаление.
- В чеке есть товар из папок `1.1.8. ПАЛЬТО` (УТ000019585), `1.1.81. ПЛАЩИ` (УТ000048136) или `1.1.82. КУРТКИ` (УТ000050308), включая подпапки.
- Магазины Business Line / BL / БЛ и «ОФИС». SoLi's и Gesolina не учитываются.
- В чеке указана дисконтная карта, и она не помечена на удаление.
- Карта не принадлежит сотруднику. Карта сотрудника — это карта:
  - из группы карт сотрудников (константа «Текущие карты сотр. группа», папка «Карта сотрудника» с подпапками, в том числе «Карты ДР сотрудников»);
  - или вида «Карта сотрудника …» (Офис, Розница, Руководители отделов). Такие виды не показываются даже в списке видов карт.
- Вид карты отмечен на шаге 2. По умолчанию отмечены карты программы лояльности, как в обработке «Начисление бонусов по новой лояльности»: new2025, VIP_30 и текущий вид карт.
- Товары акции из чека вернули не полностью. Возвраты ищутся в двух местах, учитываются только проведённые документы:
  - чеки ККМ «Возврат», у которых в «Чек ККМ продажа» указан этот чек;
  - документы «Возврат товаров от покупателя», у которых в строке товаров в колонке «Чек ККМ» указан этот чек. Так оформляют возврат не в день покупки.

  При частичном возврате (из двух вещей акции вернули одну) карта остаётся в начислении. Если чек карты вернули полностью, а у неё есть другой чек акции, бонусы начисляются за другой чек.
- По этой карте бонусы этой акции ещё не начислялись. Если у карты несколько чеков акции, берётся первый по времени.

Пропущенные чеки с причиной выводятся в окно сообщений.

## Как пользоваться

1. Войдите в Розницу с правами на создание и проведение «Начисления бонусов покупателей». Откройте файл через «Файл → Открыть».
2. Отметьте виды дисконтных карт.
3. Проверьте список: по одному чеку на карту. Галочки можно снять.
4. Подтвердите. Будет создан и проведён документ с комментарием «Доп. бонусы 10000 по акции 22.10-05.11.2026 за куртки, пальто, плащи», и он откроется. Запись также попадает в журнал регистрации (событие `НачислениеДопБонусов_АкцияВерхняяОдежда`).

Обработку можно запускать повторно: карты, которым уже начислено, она пропускает. Чтобы отменить начисление, пометьте документ на удаление.

## Как заполняются строки документа

| Поле | Значение |
|---|---|
| Дисконтная карта, Магазин | из чека |
| Док номер, Док дата | номер и дата чека, за который начислено |
| Док тип | `Акция куртки, пальто, плащи 22.10-05.11.2026` |
| Количество, Сумма покупки | количество (за вычетом возвратов) и сумма товаров акции в этом чеке |
| Сумма бонусов | 10 000 |
| Срок годности вкл | 30.11.2026 23:59:59 |
| Тип бонуса | Дополнительный |

В «Док тип» нарочно записан не «Чек ККМ». Если чек с оплатой бонусами перепровести, модуль чека ищет документ начисления по «Чек ККМ» + номер + дата + магазин + карта и перезаписывает найденный документ строкой списания. С «Чек ККМ» в «Док тип» начисление по акции могло бы так пропасть.
